# SaaS 产品二次审计（2026-09-16）

> 范围：`feat/saas-cloud`。本轮明确跳过 CUDA 真机验证与自动微信/支付宝支付接入。

## 本轮已修正

- 数字人资产由“Avatar + VoiceProfile + Asset 技术对象”改为用户视角的完整数字人：人物头像、母版视频、默认克隆声音、授权记录、可用状态。
- 创建数字人支持直接上传头像和母版视频，支持浏览器麦克风录音、上传参考录音、选择已有声音。
- 课程默认继承数字人声音，单独覆盖声音降级到高级设置。
- 新增课程 PPT/PDF 内容解析接口，课程工作台可按页生成并编辑讲稿，而不是要求用户编辑原始 JSON。
- 新增课程 readiness 检查，检查 PPT、数字人、母版、声音、授权和讲稿完整性。
- 新增账号资料修改、当前密码校验后的密码修改。
- 设置页展示肖像/声音授权记录并允许管理员撤销。
- 运营后台展示用户启停、最近审计日志、订单和内容举报处理队列。
- 已生成成片增加浏览器在线播放预览，同时保留下载。
- UI 重构为极简深色科技风，统一导航、卡片、表格、弹窗、状态、套餐、任务和课程编辑体验。
- CI 新增浏览器 JavaScript 语法检查，并继续使用 PostgreSQL + Redis 做控制面测试。

## 当前仍需保留为未完成/后续版本

### P1：正式 SaaS 产品能力

1. **邮箱验证与找回密码**
   - 当前支持注册、登录和已登录状态下修改密码。
   - 尚未接入邮件发送、邮箱验证、忘记密码邮件和一次性重置 Token。

2. **成员邀请流程**
   - 当前被邀请成员必须先注册，Owner 再通过邮箱加入。
   - 正式产品应支持邀请邮件、待接受邀请、邀请过期和撤销。

3. **课程可视化编排器**
   - 当前 SaaS 已支持逐页讲稿和页面版式（画中画/分屏/全屏课件/全屏讲师）。
   - 尚未完整迁移本地版的自由拖拽、缩放、背景演播厅和实时画布预览。

4. **PPT 页面视觉缩略图**
   - 当前 SaaS 可解析标题、正文、备注和讲稿。
   - 尚未在课程编辑器中渲染每页 PPT 缩略图。正式产品建议异步生成缩略图并缓存为 Asset。

5. **真实克隆声音试听**
   - 当前数字人卡片可试听参考录音。
   - 尚未提供“输入一句测试文本 -> CosyVoice 合成试听”的 SaaS 接口；该能力需要有 TTS Worker 或可调用的 TTS 服务。

6. **成片版本历史**
   - 当前成片支持在线播放预览与下载。
   - 后续应增加重新生成版本、历史版本、复制课程和回滚。

### P1：账号/工作区管理

7. **工作区生命周期**
   - 缺少重命名工作区、转移 Owner、删除工作区、退出工作区。

8. **Token 会话管理**
   - JWT 当前为无状态 Access Token。
   - 改密码后已签发 Token 不会立即失效。正式生产建议引入 refresh token/session/token version 或撤销列表。

### P1：正式支付和运营

9. **微信/支付宝自动支付**
   - 当前正式可用路径仍是人工订单 + 平台管理员确认收款。
   - 缺少真实商户下单、回调验签、支付幂等、退款和对账。

10. **账单与发票**
    - 尚未实现企业抬头、发票申请、账单下载、续费提醒。

### P1：生产安全与内容治理

11. **文件内容级安全扫描**
    - 当前有扩展名、大小、租户权限和存储隔离。
    - 仍应增加 MIME/魔数校验、恶意文件扫描、视频/音频解码验证。

12. **自动内容审核服务**
    - 已有授权、AI 标识、举报与人工处理模型。
    - 尚未接第三方或自建自动内容审核模型/服务。

13. **数据保留与自动清理**
    - 尚未实现套餐级留存周期、过期素材自动清理、删除任务和对象存储生命周期策略。

### P1：兼容接口收口

14. **旧 `/avatars` / `/voices` 技术接口仍保留**
    - 新产品界面已统一使用 `/digital-humans` 聚合流程，不会让普通用户直接创建不完整人物/声音。
    - 为兼容已有测试和旧页面，旧技术接口目前仍存在。正式公开 API 前应将其降为只读兼容层，或收紧为与数字人聚合接口相同的完整性校验。

15. **旧课程渲染接口依赖持久化 `course.voice_profile_id`**
    - 新课程工作室在提交生成前会执行 normalize/readiness，因此正常产品流程会继承数字人的默认声音。
    - 若第三方绕过产品流程直接调用底层 render API，仍建议后续在服务端统一实现 `course override -> avatar default voice` 的最终解析逻辑。

16. **通用素材 API 的 kind 属于调用方声明**
    - 数字人聚合接口已经校验 image/video/audio 类型，课程工具也会校验课件后缀。
    - 通用 `/assets` 接口后续仍应增加文件魔数/MIME 与 kind 的强一致性校验。

### P2：前端工程化与规模化体验

17. **前端需要从增强层收口为独立工程**
    - 当前视觉和交互已经重构，但仍基于 FastAPI 内嵌 HTML + 多个增强 JS/CSS 资源，适合快速验收和产品验证。
    - 正式长期开发建议迁移为独立 Vue/Vite 前端，建立组件库、路由、状态管理、类型定义和端到端测试，避免功能继续叠加后维护成本升高。

18. **搜索、筛选、分页**
    - 数据量小时可用；用户/课程/素材/任务较多后需要服务端分页和检索。

19. **通知中心**
    - 尚无站内通知、邮件通知或 Web Push；生成完成后目前依赖用户主动查看。

20. **审计日志筛选和导出**
    - 后端已有 AuditLog，当前运营前端也可查看最近审计；仍可继续增强筛选、导出和按租户追踪。

## 本轮验收边界

在不考虑 CUDA、自动支付和邮件基础设施的前提下，本轮目标是：

`注册/登录 -> 创建完整数字人 -> 创建课程并上传 PPT -> 自动解析逐页讲稿 -> 提交 Mock 任务 -> Redis Worker -> 成片 Asset -> 在线预览/下载 -> 额度结算 -> 授权/运营管理`

这条链路应完整可验收。
