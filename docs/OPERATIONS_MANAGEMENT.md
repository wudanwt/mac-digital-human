# SaaS 运营管理中心

## 第一阶段目标

把现有“套餐 + 额度 + 人工订单”能力收口成可以真实运营的闭环：

```text
客户注册
  -> 客户/工作区
  -> 套餐
  -> 人工订单或客户下单
  -> 收款确认
  -> 当前订阅
  -> 订阅周期历史
  -> 权益/额度发放
  -> 使用扣减
  -> 客户详情追踪
  -> 续费 / 升级 / 人工补偿
```

## 数据模型

- `Subscription`：当前可执行的订阅状态，供生成、存储、数字人/成员上限校验使用。
- `SubscriptionPeriod`：不可变的商业历史，记录每次开通/续费对应的套餐、订单、金额、时间、额度和操作人。
- `PaymentOrder`：付款事实。第一阶段支持人工订单与已有 mock 开发支付。
- `UsageLedger`：生成预扣/结算/退款和人工额度调整流水。
- `AuditLog`：平台管理员操作追踪。

不要用 `Subscription` 单表同时承担“当前状态”和“商业历史”；后者必须通过周期记录追溯。

## 运营 API

前缀：`/api/saas/admin/ops`

- `GET /overview`：客户数、付费客户、有效订阅、收入、即将到期、累计生成。
- `GET /customers`：客户搜索和当前套餐状态。
- `GET /customers/{tenant_id}`：客户 360° 详情，包括资源、订阅周期、订单、额度流水和审计。
- `POST /customers/{tenant_id}/activate`：人工开通、升级或续费，并自动创建已付款人工订单和订阅历史。
- `POST /customers/{tenant_id}/credits`：人工赠送/扣减生成分钟。
- `GET /plans`、`POST /plans`、`PATCH /plans/{code}`：套餐运营管理。

所有接口要求平台 `superuser`。

## 开通与续费规则（V1）

### replace

用于首次开通、升级或直接替换套餐：

- 立即生效。
- 当前剩余额度重置为 `套餐月分钟 × 月数`。
- 有效期从当前时间开始，按 `30 × 月数` 天计算。
- 生成一条已付款人工订单和一条 SubscriptionPeriod。

### renew

用于同套餐提前续费：

- 当前订阅仍有效且套餐相同时，从当前到期日向后顺延。
- 新购买额度追加到当前剩余额度。
- 历史周期从原到期日开始记录。
- 若当前订阅已过期或套餐不同，则按新周期生效。

第一阶段把多月合同的额度一次性发放，便于人工运营快速闭环。后续若需要“每自然月自动刷新额度”，再增加 billing cycle scheduler，不在当前阶段伪装实现。

## 后续阶段

第二阶段再接：

- 微信 / 支付宝真实下单、验签回调和支付幂等。
- 退款与对账。
- 企业发票。
- 到期、额度不足、生成完成通知。
- 优惠券、加量包。
- MRR / ARR / ARPU / 留存等订阅经营指标。
